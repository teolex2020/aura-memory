# E26: порядок у контексті з походженням — результати

Протокол: `PROTOCOL.md` (заморожено до даних; D1 — хеш; D2–D4 — звітна
модель `gemini-3.1-flash-lite` замість `qwen3-vl:8b`). 136 нових випадків
(uk/en), тестова збірка `patches/variants.py`. qwen і gemma — по 3 прогони
(шлюзи для обох), flash-lite — 1 прогін (звітне).

## Варіанти

- **C** — поточний формат (недовірене в кінці, порядок за оцінкою пошуку).
- **U** — недовірене першим, слова користувача останніми.
- **UR** — U + у кожній секції найдоречніший запис останнім.
- **URD** — UR + дати без часу доби.

## Що з'ясовано

- **Вплив порядку залежить від моделі.** gemma вірить останньому
  прочитаному: недовірене першим знижує її успіх атак з 57.5% до 28.3%.
  qwen і flash-lite навпаки: з недовіреним першим атаки вдаються частіше.
  Універсального найкращого порядку немає.
- **Порядок за доречністю** допомагає qwen у питаннях про час (81% → 94%),
  але шкодить фактам про особу (77% → 62%).
- Для малих моделей захист і далі залежить від конкретної моделі; для
  сильнішої (flash-lite) поточний формат майже непробивний (1.3%).

## Межі

Три невеликі моделі; дані синтетичні, один автор.
