# Aura як мозок: модель — орган, а не пам'ять — інструмент

Проєкт архітектури, 2026-10-07. Це документ для рішення, а не план
вбудовування. Кожен крок перед впровадженням проходить експеримент
(правило «спершу експеримент»).

## 1. Чому

**Проблема.** Зараз пам'ять Aura — зовнішній інструмент, який модель
викликає або ні. Аудит пам'яті власника (2026-10-07) показав: за 4 дні
8 239 подій від хуків і **одне** звернення до пам'яті. 298 записів, і
жоден ні разу не пригадано. Користь пам'яті залежить від того, як
навчили модель, а не від нас.

**Що ми вже вміємо.** За останній тиждень ми довели, що вміємо правильно
читати і захищати пам'ять:

| Що | Доказ |
|---|---|
| Походження за каналом запису не підробити | E51: 0 з 64 спроб «відмивання» |
| Підтвердження дій після даних ззовні зупиняє атаки через дії | E49: 48% → 0% |
| Ланцюжок фактів + перевірка новішого | E52/E52b: багатокрокові 10% → 40%, прості 82% → 96% |
| Ланцюжок захищає від згадки лише разом із позначкою «ззовні» | E53: 81% → 10% |
| Відповіді ШІ — з журналу, не з пам'яті | E56: 86,7% проти 85,0% у «всієї розмови» |
| «Правий користувач» у фактах робить модель підтакувачем | E54: 79,5% хибних уявлень повторено |

**Чому це не працює зараз.** Кожен із цих результатів вимагає, щоб хтось
керував циклом:
- вирішував, що покласти в контекст ще до відповіді;
- читав пам'ять у кілька кроків;
- перехоплював дію моделі перед виконанням.

Інструмент, який модель «може викликати», нічого з цього не вміє.

**Принцип.** Мозок веде цикл, модель — його орган (у лабораторії: «вухо,
рот і мовний орган»). Мозок не вирішує, що є правдою. Він тримає
твердження разом з їхнім походженням, будує з них ланцюжки, позначає, що
ззовні, і не дає діям із наслідками відбутися без людини, коли в розмову
потрапило чуже.

## 2. Як мозок дістається до моделі: три режими

Огляд клієнтів, перевірений на офіційній документації 2026-10-07:

| Режим | Як працює | Де | Скільки контролю |
|---|---|---|---|
| **А. Хуки** | клієнт сам викликає мозок на ключових точках ходу; облікові дані не чіпаємо | Claude Code (CLI, VS Code); Codex; Gemini CLI (`BeforeModel` навіть переписує запит); Copilot у VS Code (Preview); Cursor (лише початок сесії) | контекст перед кожним ходом, дозвіл або заборона кожної дії, спостереження за результатами |
| **Б. Локальний проксі** | клієнт шле запити моделі на `127.0.0.1`, мозок вирішує, що передати далі | Claude Code з API-ключем; Codex (і з входом ChatGPT); Gemini CLI з API-ключем; Copilot BYOK; будь-що поверх LM Studio / Ollama | повний: весь запит і вся відповідь |
| **В. Інструмент (MCP)** | як зараз, запасний варіант | Claude Desktop, ChatGPT (лише віддалено), Windsurf | лише коли модель сама спитає |

**Юридична межа, яку не можна перейти.** Anthropic прямо забороняє
стороннім застосункам пропускати запити через облікові дані підписки
Free/Pro/Max і бути посередником для токенів Claude.ai
(code.claude.com/docs/en/legal-and-compliance). Тому:

| Клієнт | Режим |
|---|---|
| Claude Code на підписці | **лише А** (хуки — це штатна функція Claude Code) |
| Claude Code з власним API-ключем користувача | Б дозволено: користування оплачує власник ключа |
| Google (вхід Google у Gemini CLI) | проксі не робити, були блокування акаунтів; лише хук `BeforeModel` |
| OpenAI (Codex з входом ChatGPT) | найменший ризик, але перевірити умови перед запуском |

**Висновок.** Основний режим — А (хуки): він легальний для підписок і вже
частково працює, бо наш міст ловить хуки 6 клієнтів. Режим Б — для тих,
хто працює з API-ключем або локальною моделлю. Режим В лишається для
клієнтів без хуків.

## 3. Один хід мозку

Однаковий для режимів А і Б. Різниця лише в тому, через що мозок бачить
хід.

| Крок | Що робить мозок | Звідки рішення |
|---|---|---|
| 1. **Вхід** | ділить повідомлення на ваші слова, вставлене і службове; ваші слова пише з каналом `user-<програма>` | аудит пам'яті; 0.1.4 |
| 2. **Розбір** (необов'язково) | модель-«вухо» витягає, про що питають: кандидати, без права писати знання | лабораторія: «тільки кандидат» |
| 3. **Пригадування** | ланцюжок фактів; на кожній ланці перевірка, чи немає новішого запису про те саме, **лише серед записів пам'яті** | E52, E52b, E53 |
| 4. **Ззовні** | вміст ззовні йде окремим блоком з позначкою; правило «не спирайся лише на нього» | E47, E53 |
| 5. **Минулі відповіді ШІ** | кілька найближчих із журналу, з позначкою «що казав ШІ тоді, не факти» | E56 |
| 6. **Факти проти слів користувача** | ваші бажання вирішуєте ви. Ваше свідчення («бачив сам») вагоміше за статтю, а переконання про загальні факти зважуються доказами | E54; розрізнення ще треба виміряти |
| 7. **Контекст** | компактний блок у **останній** хід, а не в системні інструкції, щоб не ламати кеш і порядок системних блоків | вимоги Claude Code до шлюзів |
| 8. **Модель** | відповідає або діє (орган) | — |
| 9. **Ворота дій** | якщо в цьому ході є дані ззовні, дія з наслідками (лист, оплата, видалення, надсилання) іде вам на підтвердження. Значення для дії мають походити від вас або з довіреного джерела | E49, E51 |
| 10. **Після** | відповідь — у журнал, не в пам'ять; нові твердження моделі — лише як «висновок ШІ»; оновлення критичного факту — лише з ≥ 2 незалежних джерел | E56; лабораторія (`memory_source_dependence`: 0% отрути) |

У режимі А кроки 1–7 робить хук перед ходом (UserPromptSubmit або
BeforeAgent з `additionalContext`), крок 9 — хук перед дією (PreToolUse:
`ask` / `deny`), а крок 10 — хуки після дії й наприкінці (PostToolUse,
Stop).

## 4. Що беремо з лабораторії як **задум** (не код)

Огляд `D:\Aura-clean`, 2026-10-07. Код лабораторії не переносимо без
експерименту.

**Беремо:**
1. **Договір «вухо — рот».** Модель розбирає вхід на кандидатів і
   формулює лише те, що їй дали. Механічна перевірка відкидає вигадані
   числа. Порожня відповідь лишається «боргом», а не вигадкою.
2. **Епістемічні позначки скрізь.** «Тільки кандидат» закладено в
   структуру, позначки довіри доходять до відповіді, мовчати дозволено.
3. **Окремі канали «корисність / підтвердження» і «правда».** Питання
   чи повтор ніколи не додають підтвердження. Це закон «проти
   газлайтингу».
4. **«Одне джерело — один голос»** під час запису і **≥ 2 незалежні
   джерела** для оновлення критичних фактів. Перекази тієї самої
   родини моделей — один голос.
5. **«Правило може заборонити, але не дати право»** (`rule_organ.rs`:
   лише Deny / Excite).
6. **Регулятор ходу:** відповісти / подумати ще / відмовитися, з
   бюджетом зупинки.
7. **Питання без відповіді стає боргом на дослідження.**
8. **Правила методу:**
   - перевіряти суддів мутаційними тестами;
   - окремі дані для налаштування і для рішення;
   - ховати очікувану відповідь від циклу самовдосконалення.

**Не беремо** (провалилося в лабораторії):
- кілька паралельних центрів влади (Rust, Python, «ядро», «нуклеус»);
  аудит лабораторії дійшов висновку «звести до мінімального ядра»;
- розростання органів: 350 файлів, 207 програм, більшість без
  реального виклику;
- судді-моделі для автоматичного прийняття фактів, голосування
  корельованих моделей;
- повільні «журі» в ході користувача (126–162 с);
- навчена пластичність, «народження» операторів чи ознак, «зшивання»
  органів як джерело здібностей (усе програло простим базовим
  рішенням);
- «розрив аудиту й рота»: система знає, а відповідає «не знаю»;
- запуски на живому стані.

**Головний урок лабораторії: одна влада.** Мозок — це одне ядро (Rust,
програма Aura). Хуки, міст і проксі лише передають, нічого не вирішують.

## 5. Ризики

| Ризик | Що робимо |
|---|---|
| Затримка: хуки мають ліміти часу, користувач чекає | пригадування до ~1 с на хід; нічого важкого в ході; «журі» поза ходом |
| Вартість у токенах: контекст росте з кожним ходом | малий бюджет (3–8 записів), лише різниця з попереднім ходом |
| Кеш підказок | вставка лише в останній хід; системне не чіпати |
| Постачальники змінюють формати й умови | режим А як основа; пересилати поля проксі «як є»; стежити за умовами |
| Приватність: через Aura йде більше даних | усе локально, як і зараз; звіт «що пішло назовні» охоплює й ці шляхи |
| Помилки мозку стають помилками моделі | кожен крок — з експериментом і можливістю вимкнути |
| Одна людина підтримує | мінімальне ядро; жодних органів без виміряної користі |

## 7. Питання до власника

1. Основний режим — хуки (А). Згодні, що проксі (Б) лише для API-ключів і
   локальних моделей?
2. Чи готові ви ходити з власним API-ключем Anthropic, а не з підпискою,
   щоб випробувати режим Б?
3. Підтвердження дій (крок 2) — це вікно Aura на кожну дію з наслідками
   після даних ззовні. В E49 це ~0,4 запиту на завдання. Прийнятно?
4. Чи повертаємо лабораторні ідеї «борг на дослідження» і «регулятор
   ходу», чи спершу лише кроки 1–3?

## Додаток А. Огляд лабораторії `D:\Aura-clean` (2026-10-07, лише читання)

**Як був побудований «гібридний мозок»** (липень 2026). Один хід — один
виклик Rust-програми `src/bin/aura-hybrid-brain-live-turn.rs`:
1. **«Вухо»:** модель повертає структуровані кандидати.
2. **Суддя-кандидат:** питання не пишуть підтвердження.
3. **Пригадування:** твердження з рівнями довіри, ланцюжки A→B→C.
4. **Матеріал з позначками довіри.**
5. **«Турбіна»:** відповісти / подумати ще / відмовитися.
6. **«Рот»:** модель формулює лише дане.
7. **Механічна перевірка рота.**
8. **«Голод»:** питання без відповіді стають боргом.

У фоні працювали «журі» з 5 локальних моделей і вебпошук. Модель
локальна: gemma-3n-E4B на llama-server, `127.0.0.1:8091`. Щоденник
закінчується 2026-07-08. Чи запускається це сьогодні, не перевіряли.
