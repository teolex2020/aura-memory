# E1b: вибіркове очищення в mem0 — результат

Дата: 2026-09-27. Протокол: [PROTOCOL.md](PROTOCOL.md), заморожений до запуску,
поправка B1 стосується лише звітування про нечитані файли.

Система: `mem0ai` 2.2.1, open-source `Memory`, локальний Qdrant на диску,
SQLite-історія за замовчуванням, `infer=False`, телеметрію вимкнено, без мережі.

## Коротко

`Memory.delete()` у mem0 прибирає отруйні записи з логічної видимості без
шкоди для нормальних, але **весь видалений вміст лишається на диску і
доступний через публічний API**. Вибіркового purge у mem0 немає.

## Гейти

| Гейт | mem0 `delete` | Aura `delete` (E1) | Aura `purge_record(History)` (E1) |
|---|:-:|:-:|:-:|
| G1 логічні залишки | PASS | PASS | PASS |
| G2 похідні дані | n/a | PASS | PASS |
| G3 вміст у файлах | **FAIL** | FAIL | **PASS** |
| G4 ID у файлах | **FAIL** | FAIL | **PASS** |
| G5 rollback не повертає | n/a | FAIL | **PASS** |
| G6 побічна шкода | PASS | PASS | PASS |
| G7 квитанція | **FAIL** | — | **PASS** |
| G8 збій на закритому сховищі | n/a | PASS | PASS |

## Де лишається видалений вміст у mem0

- **`history.db`**: 8 із 8 отруйних текстів і ID. Це задум, а не збій:
  `_delete_memory` записує `prev_value` у таблицю історії з подією `DELETE`.
- **`Memory.history(id)`** повертає видалений текст для 8 із 8 записів через
  звичайний публічний API. Хто має доступ до SDK, той читає «видалене».
- **`qdrant/.../storage.sqlite`**: 6 із 8 текстів і ID залишаються у байтах
  файлу після видалення точок (SQLite не затирає звільнені сторінки).
- Після reopen нічого не змінилося.

Єдиний спосіб у публічному API прибрати ці сліди — `reset()` або `delete_all()`
для всього scope, тобто знищити й нормальні записи.

## Що це означає

- На рівні «запис більше не видно агенту» mem0 і Aura поводяться однаково.
- На рівні «запис справді зник» mem0 не має інструменту, а Aura має
  `purge_record`, який пройшов усі гейти E1.
- Це прямо стосується GDPR (право на видалення) і сценарію отруєння пам'яті:
  отруту в mem0 можна сховати від агента, але не прибрати.

## Межі

- Одна конфігурація mem0 (Qdrant на диску + SQLite). Інші векторні сховища,
  граф-пам'ять, `infer=True` і хмарна платформа mem0 не перевірялися.
- Ембедер детермінований лексичний, не семантичний. Це впливає лише на пошук,
  не на видалення чи залишки байтів.
- Фікстуру написав той самий автор, що й E1; порівняння рівне, але не незалежне.
- Висновок про `history.db` підтверджено і вимірюванням, і кодом mem0
  (`mem0/memory/main.py`, `_delete_memory`).
